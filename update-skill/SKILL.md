# Skill 自我完善流程

以下情况应触发本流程：

**任务完成后用户反馈类（使用了 skill）：**
- 对结果不满意，要求修改或重做
- 提出了 skill 未覆盖的新要求或边界情况
- 纠正了你的做法，给出了更好的方案
- 明确说"以后都要这样做"或类似的持久化意图

**用户主动总结类（无论是否使用了 skill）：**
- 用户说"总结上文，更新 skills"或类似表达时，即使本次未调用任何 skill，也应主动回顾对话，分析是否有值得沉淀的经验，识别出对应的 skill，并走完整的确认→更新流程

## 判断标准

**应该更新 skill 的情况：**
- 用户的反馈揭示了 skill 流程中的缺陷或遗漏
- 用户提出的要求具有通用性，未来再次执行同类任务时也应遵循
- 用户纠正的做法比 skill 中记录的更好

**不应该更新 skill 的情况：**
- 用户的要求是一次性的、特定于当前任务的
- 反馈仅涉及个人偏好且用户未表达持久化意图
- skill 本身没有问题，只是当前场景特殊

## 执行流程

### Step 1：识别并询问

当检测到上述触发条件时，向用户确认：

> 你的这个反馈看起来可以改进 [skill 名称] skill，让以后类似任务都按这个方式处理。需要我更新 skill 吗？

简要说明打算更新什么内容，让用户决定。

### Step 2：读取并更新

用户同意后：

1. 用 `Read` 工具读取对应的 `~/.Codex/skills/<skill-name>/SKILL.md`
2. 用 `Edit` 工具将改进内容更新到合适的位置
3. 保持 skill 文件的现有结构和格式
4. 更新内容应简洁明确，不要冗余

### Step 3：确认

更新完成后，简要告知用户修改了什么内容。

## 注意事项

- 始终先征求用户同意，绝不自行决定更新 skill
- 只更新与反馈直接相关的部分，不要大幅重写 skill
- 如果 skill 的 description（YAML 头部）也需要调整，一并更新
- 如果 AGENTS.md 中的触发条件描述也需要调整，一并更新
