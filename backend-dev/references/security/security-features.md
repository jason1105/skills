# 安全功能要求

本文档整理自等保测评和第三方安全检测的安全功能要求，涵盖认证鉴别、访问控制、安全审计、数据保护、会话管理五大领域。
详细设计和 DDL 设计阶段参照本文档进行安全架构设计。

---

## 1. 认证鉴别

### 1.1 用户标识

| 要求 | 说明 |
|------|------|
| 身份鉴别 | 必须提供专用或统一的登录控制模块，鉴别过程在服务端完成 |
| 标识唯一 | 提供用户身份标识唯一性检查，系统中不存在重复标识的用户 |
| 实名制 | 不内置匿名账号，按实名制原则创建账号（等保二级：绑定手机号；三级：绑定身份证） |

### 1.2 口令规范

| 要求 | 说明 |
|------|------|
| 复杂度 | 长度 ≥ 8 位，大写字母、小写字母、数字、特殊字符中 ≥ 3 种组合 |
| 禁止弱口令 | 口令不能与用户名相同或包含用户名 |
| 有效期 | 强制至少每 3 个月修改一次，且前后不能完全一样 |
| 初始口令 | 为每个用户创建独立且满足复杂度要求的初始口令 |
| 首次登录 | 新建用户首次登录必须先修改初始口令 |
| 变更权限 | 除管理员外，用户只能修改自己的口令 |

### 1.3 鉴别机制

| 要求 | 说明 |
|------|------|
| 重鉴别 | 执行敏感操作时重新鉴别用户身份 |
| 防重放 | 身份鉴别过程具备防重放机制 |
| 多因素鉴别 | （等保三级）采用两种或以上组合鉴别技术（静态口令 + 动态口令/证书/生物特征） |
| 失败处理 | 24 小时内连续失败次数达到设定值（1-10 次内）时锁定账号，至少锁定 20 分钟 |

### 1.4 账号生命周期

| 要求 | 说明 |
|------|------|
| 账号分类 | 按使用周期分为长期使用和临时使用，临时账号最长 3 个月 |
| 账号状态 | 分为激活、休眠、注销三种状态 |
| 自动扫描 | 至少每月自动扫描一次，3 个月及以上未使用的账号转为休眠 |
| 休眠账号 | 无法登录，保留角色和权限，经管理员审批后可激活 |

## 2. 访问控制

| 要求 | 说明 |
|------|------|
| 授权控制 | 仅允许授权的管理员配置访问控制策略 |
| 最小权限 | 未授权用户仅具有最低级别权限（修改自身信息 + 有限查询） |
| 角色体系 | 至少设置四种角色：系统管理员、审计管理员、审核管理员、业务操作员。前三者为内置角色，实现"操作-审批"分权制衡 |
| 角色互斥 | 不同角色间权限互斥，不能将不同角色授予同一用户 |
| 管理员权限边界 | 系统管理员仅具有用户/角色/权限管理和系统运维权限，不可操作业务数据和审计记录 |
| 审计员权限边界 | 审计管理员仅具有操作轨迹监控和审计数据管理权限 |
| 审核员权限边界 | 审核管理员负责审批用户创建、权限变更等敏感操作，与系统管理员分离 |
| 防越权 | 防止横向越权（同级用户间）和纵向越权（低权限访问高权限功能） |
| 安全标记 | 对重要信息资源设置敏感标记，依据标记进行访问控制，高敏感数据访问留痕 |

---

## 3. 安全审计

| 要求 | 说明 |
|------|------|
| 审计全面性 | 记录登录成功/失败、退出、用户增删改、密码重置、导出日志等系统级事件和业务操作 |
| 事件分类 | 至少分为系统级事件和业务级事件 |
| 记录内容 | 每条记录包含：日期、时间、事件类型、用户身份、事件描述、事件结果 |
| 查询排序 | 提供对审计数据进行查询和排序的功能 |
| 异常告警 | 对异常审计事件按严重程度分级，采用弹窗/声光/短信/邮件等方式告警 |
| 审计保护 | 审计记录不可被非审计管理员修改或删除 |
| **私密信息审计保护** | 审计记录中的私密信息（密码、token、身份证号、手机号等）必须脱敏或加密存储，避免审计日志本身泄露敏感信息 |

---

## 4. 数据保护

### 4.1 传输安全

| 要求 | 说明 |
|------|------|
| 完整性 | 采用校验码或密码技术保证重要数据传输过程中的完整性 |
| 保密性 | 采用密码技术保证重要数据传输过程中的保密性 |
| 加密算法 | 使用国家密码主管部门要求的加密算法（国密 SM2/SM3/SM4） |

### 4.2 存储安全

| 要求 | 说明 |
|------|------|
| 存储加密 | 重要数据（鉴别信息、敏感业务数据、个人信息）加密存储 |
| 禁止明文 | 服务端不以明文形式存储重要数据 |
| 数据库连接 | 数据库连接的用户名和密码必须加密，连接建立后清空内存中的密码信息 |
| IV 和 Key 分离 | 加密的初始化向量 IV 和密钥 Key 应分开存放 |

### 4.3 数据脱敏

| 要求 | 说明 |
|------|------|
| 个人信息展示 | 涉及的用户个人信息（手机号、身份证号等）应去标识化后展示 |
| 日志脱敏 | 日志中不输出敏感字段（密码、token、完整路径） |

### 4.4 输入验证

| 要求 | 说明 |
|------|------|
| 有效性检验 | 对人机接口和通信接口输入的数据做格式校验 |
| 防注入 | 通用防注入校验（SQL 注入、XSS、命令注入等） |
| 业务校验 | 业务相关的数据验证规则在业务层实现 |

---

## 5. 会话管理

| 要求 | 说明 |
|------|------|
| 超时终止 | 用户会话非活动超时终止，时间设置 > 0 且 ≤ 30 分钟 |
| 并发限制 | 对最大并发会话连接数进行限制 |
| Cookie 安全 | Cookie 中不包含敏感信息（用户名、密码），设置 HttpOnly、Secure、SameSite |
| JWT 安全 | 若使用 JWT，不使用弱加密算法（如纯 base64），应使用强签名算法 |

---

## 6. 基础设施安全

| 要求 | 说明 |
|------|------|
| 无关端口 | 关闭与业务无关的服务端口 |
| 管理端口 | 操作系统/中间件/数据库管理端口在默认端口号基础上 +10000 |
| 中间件后台 | 屏蔽中间件后台管理页面 |
| 版本隐藏 | 不泄露中间件版本信息，定制错误页面 |
| HTTP 方法 | 仅允许 GET 和 POST，关闭 PUT/DELETE/OPTIONS 等方法（RESTful 架构按实际需要开放） |

## 设计自检清单

详细设计完成后，对照以下清单确认架构已覆盖：

- [ ] 认证模块设计覆盖口令复杂度、有效期、失败锁定、防重放
- [ ] 权限模型包含系统管理员、审计管理员、业务配置员三种角色
- [ ] 审计模块记录系统级和业务级事件，包含完整的 6 要素
- [ ] 数据传输有加密方案（考虑国密要求）
- [ ] 敏感数据存储有加密方案，数据库连接密码加密
- [ ] 个人信息展示有脱敏方案
- [ ] 会话管理有超时和并发控制
- [ ] Cookie/JWT 安全策略已明确
