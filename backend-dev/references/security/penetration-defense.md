# 渗透防护要求

本文档整理自渗透检测实际结果和标准测试用例，涵盖 21 类渗透测试检测项。
详细设计和 API 接口设计阶段参照本文档设计防护措施。

---

## 高危漏洞

### 1. 越权访问

**检测内容**：对不同用户、不同角色的权限和数据进行隔离，不存在横向和纵向越权。

**实际案例**：通过抓包将业务审计员的 cookie 替换为业务操作员的 cookie，实现越权操作。

**防护对策**：

- 每个接口在 Service 层校验当前用户是否有权操作目标资源
- 增加 unique-token 机制：为每个登录成功的 cookie 分配唯一 token，后续请求比对
- 数据查询加入用户维度过滤（如 `WHERE user_id = currentUserId`）

### 2. 密码明文传输

**检测内容**：系统数据传输应对关键数据进行加密处理。

**防护对策**：

- 登录接口的用户名和密码在前端加密后传输
- 使用 HTTPS 传输
- 考虑国密算法要求（SM2/SM3）

### 3. 用户凭证暴力破解

**检测内容**：用户密码不应明文显示，应有防暴力破解机制。

**防护对策**：

- 密码加密传输和存储
- 登录失败限制（连续 N 次锁定，至少 20 分钟）
- 图形验证码（≥ 4 位字符，含字母和数字，扭曲处理）

### 4. 关键会话重放攻击

**检测内容**：关键业务功能所使用的协议应具备抗重放功能。

**实际案例**：重放登录接口请求，暴力破解账号密码。

**防护对策**：

- 请求中包含时间戳 + 随机数 + 签名，服务端校验有效期和唯一性
- 关键操作接口使用一次性 token

### 5. CSRF（跨站请求伪造）

**检测内容**：服务端应严格验证客户端请求来源的合法性。

**防护对策**：

- 校验 Referer / Origin header
- 使用 CSRF Token
- Nginx 配置防止被 iframe 引用（`X-Frame-Options: DENY`）
- Cookie 设置 `SameSite=Strict`

### 6. 不安全的 Cookies

**检测内容**：Cookie 中不存在密码等敏感信息。

**实际案例**：cookie 的 token 中包含了用户名。

**防护对策**：

- Cookie 中不包含用户名、密码等可识别信息，使用随机 ID
- 设置 `HttpOnly`、`Secure`、`SameSite`
- JWT 不使用 base64 弱加密，应使用强签名算法

## 中低危漏洞

### 7. SQL 注入

**检测内容**：对外部输入做严格过滤，使用参数绑定防止注入。

**防护对策**：

- 使用参数化查询（MyBatis `#{}`、PreparedStatement）
- 全局输入过滤器拦截 SQL 关键字
- 详见 `secure-coding.md` 第 7 条

### 8. XSS 漏洞

**检测内容**：对外部输入做严格过滤，防止脚本注入。

**防护对策**：

- 后端输出到前端的数据做转义处理
- 前端对展示数据做过滤或转义输出
- 对常用特殊字符（如中文逗号、句号）不过滤，仅过滤危险字符
- 详见 `secure-coding.md` 第 3 条

### 9. 文件上传漏洞

**检测内容**：文件上传功能应对文件类型做限制。

**防护对策**：详见 `secure-coding.md` 第 8 条

### 10. 命令执行漏洞

**检测内容**：严格验证和过滤用户数据，避免命令拼接。

**防护对策**：详见 `secure-coding.md` 第 1 条

### 11. 目录遍历 / 任意文件下载

**检测内容**：不存在目录遍历安全问题，不允许下载规定以外的文件。

**防护对策**：详见 `secure-coding.md` 第 5 条

### 12. XML 实体注入

**检测内容**：XML 格式数据服务端应具备防篡改验证功能。

**防护对策**：详见 `secure-coding.md` 第 2 条

### 13. SSRF（服务端请求伪造）

**检测内容**：对外部输入的 URL 做严格过滤。

**防护对策**：

- 白名单限制可请求的域名/IP
- 禁止请求内网地址（127.0.0.1、10.x、172.16-31.x、192.168.x）
- 禁止使用 file:// 协议

### 14. 后台地址泄露

**检测内容**：关闭中间件管理后台，隐藏应用系统自带后台。

**防护对策**：

- 关闭中间件管理后台页面（如 Druid Monitor、Actuator endpoints）
- 通过反向代理限制管理接口访问

### 15. 敏感信息泄露

**检测内容**：客户端不应暴露服务器路径、源代码、版本信息、详细报错。

**防护对策**：

- 统一异常处理，生产环境不返回堆栈信息
- 定制错误页面（404、500）
- 隐藏中间件版本（Server header）

### 16. CORS 漏洞

**检测内容**：应禁止任意跨域请求。

**防护对策**：

- 项目默认不开启 CORS
- 如需开启，严格配置允许的 Origin 白名单
- 不使用 `Access-Control-Allow-Origin: *`

### 17. 未经授权的修改

**检测内容**：虽然画面做了限制，但通过修改 request 仍可修改后台数据。

**防护对策**：

- 服务端必须做权限校验，不依赖前端控制
- 所有写操作接口校验当前用户是否有权执行
- 只读字段在服务端强制忽略（不从请求参数取值）

### 18. 不安全的 HTTP 方法

**检测内容**：关闭除 GET 和 POST 以外不安全的 HTTP 方法。

**防护对策**：

- 如非 RESTful 架构，仅允许 GET 和 POST
- RESTful 架构按实际需要开放，但需确保每个端点都有权限控制

### 19. SSL 漏洞

**检测内容**：使用的加密套件不存在已知安全漏洞。

**防护对策**：

- 禁用 SSLv3、TLS 1.0、TLS 1.1
- 使用 TLS 1.2+ 和安全的加密套件

### 20. 默认口令/弱口令

**检测内容**：认证模块应使用强口令，不能使用预置口令。

**防护对策**：

- 不预置默认密码
- 口令强度策略在服务端强制校验

### 21. 登录验证码漏洞

**检测内容**：验证码不能被破解，不能被重复使用。

**防护对策**：

- 验证码一次有效，校验后立即失效
- 服务端生成和校验，不依赖前端

### 22. 设计缺陷 / 逻辑错误

**检测内容**：业务逻辑是否存在漏洞，使攻击者能绕过正常流程达成非预期结果。

**典型案例**：

| 类型 | 案例 | 防护对策 |
|------|------|---------|
| **金额/数量越界** | 购买数量传负数导致退款、折扣叠加超过 100% | 服务端严格校验数值范围和计算结果 |
| **并发条件竞争** | 同一优惠券被同时兑换两次、秒杀超卖 | 使用乐观锁（版本号）或悲观锁（数据库行锁），关键操作加分布式锁 |
| **状态机绕过** | 跳过"待审核"状态直接改为"已通过" | 状态流转严格按照状态机定义，禁止直接赋值；每次流转校验前置状态 |
| **任意用户操作** | 通过修改请求中的 userId 操作他人数据 | 从会话/Token 提取当前用户 ID，忽略请求中的 userId 字段 |
| **短信/邮件轰炸** | 短信接口无频率限制，被用于骚扰他人 | 按手机号/IP 做频率限制（如 1 分钟 1 次、1 小时 5 次） |
| **重置密码链接复用** | 重置密码链接可多次使用或永久有效 | 一次性 token，使用后立即失效，设置短有效期（如 15 分钟） |
| **支付金额篡改** | 前端计算订单金额，请求中可修改 | 服务端根据商品 ID 和数量重新计算金额，不信任前端传入的总价 |
| **越权查询** | 查询接口返回所有用户数据，前端过滤显示 | 服务端按当前用户权限过滤数据，不依赖前端 |
| **订单号枚举** | 订单号连续递增，可枚举他人订单详情 | 使用 UUID 或雪花 ID，不使用自增 ID 暴露给前端 |
| **文件访问未授权** | 文件下载只校验文件是否存在，不校验当前用户是否有权访问 | 文件访问需检查当前用户与文件的归属关系 |

**检测方法**：

- **代码审查**：关注所有涉及金额、状态流转、权限判断的代码
- **业务流程测试**：构造异常流程（跳步骤、改状态、改参数）验证系统行为
- **并发测试**：对关键操作做并发测试，验证幂等性和一致性

**设计阶段防护要求**：

- 详细设计文档中必须明确每个业务流程的状态机
- 所有涉及金额的计算必须在服务端完成
- 所有权限判断必须基于会话中的用户身份，不信任请求参数中的用户标识
- 关键操作有幂等性设计（如订单号唯一、token 一次性）

## API 设计自检清单

API 接口设计完成后，对照以下清单确认：

- [ ] 所有写操作接口有权限校验（不依赖前端）
- [ ] 登录接口有失败锁定 + 验证码 + 防重放机制
- [ ] 敏感操作接口有重鉴别机制
- [ ] 输入参数有校验规则（类型、长度、格式、白名单）
- [ ] 文件上传接口有类型/大小/内容校验
- [ ] 文件下载接口有路径校验 + 防遍历
- [ ] 数据展示接口有脱敏处理
- [ ] 错误响应不暴露堆栈和内部信息
- [ ] CORS 配置为最小必要范围
- [ ] Cookie 设置了 HttpOnly、Secure、SameSite
- [ ] 业务金额计算在服务端完成，不信任前端传入
- [ ] 用户身份从会话获取，不信任请求参数中的 userId
- [ ] 关键操作有幂等性保护（一次性 token / 版本号 / 分布式锁）
- [ ] 涉及状态流转的接口校验前置状态合法性
- [ ] 短信/邮件/验证码接口有频率限制
