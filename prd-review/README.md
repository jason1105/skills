# prd-review

B 端 PRD 文档规范性评审 Skill，聚焦三章：**交互与状态（§4）**、**数据与字段定义（§6）**、**接口清单（§7）**。

---

## 快速配置

1. 将本目录复制到 `~/.claude/skills/prd-review/`
2. 在 Claude Code 中，任何 "评审 PRD / 检查需求文档" 类指令将自动触发本 skill

无需额外安装依赖，开箱即用。

---

## 使用方式

```
/prd-review 评审 '路径/到/你的PRD.pdf'
```

或者直接说：

> "帮我评审一下这份 PRD"  
> "检查一下这个需求文档写得怎么样"  
> "PRD 自检"

Skill 会自动：
1. 读取 PRD 文档（支持 PDF / Markdown）
2. 对照 `rules/PRD编写规则.md` 逐项核查
3. 生成 `<原文件名>-评审报告.md`，与 PRD 同目录
4. 输出结论：通过 / 有条件通过 / 打回

## 迭代改进

### 修改评审规则

编辑 `rules/PRD编写规则.md`：
- `§4` 交互与状态的写法要求
- `§6` 数据与字段定义的写法要求
- `§7` 接口清单的写法要求
- 附录 A/B/C（评审流程、常见打回理由、FAQ）

修改后在 `CHANGELOG.md` 追加一条版本记录，并更新 `SKILL.md` 报告页脚的版本号。

### 修改评审行为

编辑 `SKILL.md`：
- **检查清单**：增删检查项、调整严重/一般级别
- **跨章一致性检查**：调整交叉比对规则
- **报告模板**：调整报告结构和文案
- **触发描述**（frontmatter `description` 字段）：调整触发词覆盖范围

### 建议的迭代流程

1. 用真实 PRD 跑一次评审，记录漏报或误报的问题
2. 定位是规则缺失（改 `rules/PRD编写规则.md`）还是检查逻辑缺失（改 `SKILL.md`）
3. 修改对应文件，重新跑同一份 PRD 验证
4. 在 `CHANGELOG.md` 记录改动原因

---

## 评审范围说明

本 skill **只评审** §4 / §6 / §7 三章，原因：这三章是产品 → 研发交接的核心，最容易导致开发返工。

§1 需求基本信息、§2 背景与目标、§3 用户角色与权限、§5 业务流程、§8 异常与边界场景、§9 验收标准、§10 非功能性要求、§11 文档元信息**均不在评审范围内**。
