# PRD 需求卡片双向溯源原型规范

## 1. 触发与流程

- 触发：用户要求生成可交互原型／需求卡片／评审材料，或迭代已有三件套（详设 MD＋卡片 MD＋HTML 原型）。任意系统适用
- 分工：`prd-detail-design` 产出《产品需求详细设计》；本 skill 消费其产出，产出**卡片 MD 与 HTML 原型两件**，详设不重复生成
- **输入判定**（三分支）：
  1. 输入含七段式详设（有「功能业务说明／交互与业务规则／验收标准」小节）→ 直接按本规范抽取
  2. 输入是 PRD／docx，无七段式 → 先跑 prd-detail-design 再接本 skill
  3. 输入是冻结 PRD 且用户明示不出详设 → 直接出卡片＋原型，卡片【4】标「置信度：推断」
- 目标仓存在 `prd-review/rules/PRD编写规则.md` 时，读其验收标准与自检清单两节；不存在则跳过，直接按本规范产出
- 已有需求稿（冻结 PRD／docx＋评审回复／基线目录）作输入时：读完全部原件，不改写口径；裁决注记（「第一版不做」「推第二期」）照录；开放疑点照录不销项；无独立验收的预留需求如实写「验收条款按框架语义验证」，不编造验收场景

## 2. 编号体系

- 需求编号 **REQ-{需求号}-xxx**：需求号取外部编号体系（禅道 story 号，如 47589）、仓内系统代称、日期或**需求基线版本号（如 v1.0）**，全期唯一不复用；所用体系在卡片 MD 文头声明
- **AC 编号＝父需求完整编号＋`-ACn`**：ac.id 必须以其所属 story.id 字面开头（story.id=`REQ-v1.0-002` → `REQ-v1.0-002-AC1`），n 从 1 连续——评审者从原型徽标/MD/覆盖表三处搜同一个号都要搜得到
- 徽标文案一律用完整需求号，不用短号或语义短标签〔事故〕短号徽标评审现场对不上卡片
- 故障注入档位标注：默认标 AC 编号；档位只对应异常条款时可写 E-REQ-xxx-n，同一文件内只选一种口径并在页脚说明
- 编号改名：三件同步换（MD＋HTML 全量替换）＋浏览器回归确认深链/卡片/FAB 徽标指向新编号

## A. 需求卡片 MD

三件套同名前缀、同目录（详见 D 节运维）。每条需求一张卡片，**标题层级固定三级、不得混用**：

```
## 模块：X
### REQ-xxx 名称　P0/P1/P2     ← 卡头＋字段表
#### 【n.节名】                ← 正文四节
```

禁止另起 `## REQ-xxx` 二级标题承载卡正文。

默认三件同名前缀同目录；原型位置深链写 `{同名前缀}.html#story=REQ-xxx`（全仓唯一例外时才是 `01-{系统}_可交互原型.html`）。卡头字段表：适用角色／模块与来源章节／优先级与分类／所属业务目标（有目标体系时）／**所属基线与版本**／原型位置深链。

正文四节固定（与抽屉卡是**同一数据的两个投影**，字段映射见 B2）：

- **【1.核心口径】**：加粗小标题的叙述段＋口径表（枚举项逐行给说明与关联 REQ）；裁决注记照录原文、单独成段。节标题不带版本号（版本在字段表）——基线升版不必改全部标题
- **【2.验收标准（GIVEN/WHEN/THEN，原文）】**：逐条 AC 完整照抄需求基线原文；禁止缩写成「AC1~ACn（一句话括注）」
- **【3.交互细节（原型要表现的行为）】**：编号列表，逐条「入口→操作→反馈→分支」，是原型的实现清单
- **【4.置信度与依据（摘要）】**：逐口径标【确证（来源）】或【推断】，与需求基线置信度行对齐

**深度底线**：四节合计是详设该功能点的忠实浓缩——枚举表逐项保留、异常分支不丢、裁决注记不丢。抽取映射：核心口径←功能业务说明＋交互与业务规则；AC←验收标准表（前置/操作/预期三列→GWT）；交互细节←交互与业务规则；置信度←需求基线置信度行。摘要级卡片（每节一两句话）不合格。

**全仓唯一持续迭代原型例外**：用户指定原型「全仓唯一、持续迭代」时，放需求目录 `00-原型/`、文件名带两位补零前缀（`01-{系统}_可交互原型.html`），后续同文件追加 REQ 族；卡片 MD 定位链接改指该文件；多族并存时页头标注（如「v1.0＋47589 两族」）。

文档末尾附修订记录表（|版本|日期|变更人|变更说明|，只追加行）。

## B. HTML 原型

### B1 技术约束

- 单文件 HTML，vanilla JS，**禁止任何外链**（`<script src>`/`<link href>`/字体 CDN/fetch 外域），所有资源内嵌，双击即开断网可用（lint⑤ 强制）
- `:root` 定义设计 token；中文字体栈微软雅黑/PingFang SC
- `localStorage` 持久化＋reset 入口
- 角色切换器覆盖 PRD 全部适用角色（交付门 G4 断言 chip 数≥角色表）＋故障注入开关（success/各异常态）
- hash 路由 `#/view/<viewKey>`＋深链 `#story=<REQ-id>`，可选 `?tab=`
- **六机制**（缺一即「演示壳」）：
  1. **seed 结构化演示数据**：完整业务对象图，字段名与详设业务对象属性表一致；不是两三行摆设
  2. **表单级交互闭环**：配置面板按来源/类型分形；保存走真实校验（必填/类型匹配/引用悬空/状态不可用），错误以清单呈现、成功持久化并反馈
  3. **故障注入驱动行为**：档位改变校验/生成路径的真实分支（类型不符→保存被拒），不是换文案
  4. **流程守卫**：formDirty（未保存拦截导航）；pendingOp 判定标准＝**任何改变业务对象状态的演示操作（上传/保存/生成/发布）执行期间置位、完成或失败即清**；纯滚动/高亮不算
  5. **STORIES 验收结构化**（schema 见 B2）；抽屉四段完整渲染
  6. **端到端可演示**：至少一条「卡片▶定位→配置→校验→保存→结果反馈」完整链路点得通（AC 逐条覆盖归 C3 覆盖表，不在此重复）

### B2 数据模型（唯一权威 schema，全文唯一出处）

`window.STORIES` 数组，每条需求一个对象；**必须是纯 JSON 字面量**（禁尾逗号/注释/单引号），`window.STORIES = [` 起始、`];` 独占一行（lint 依赖此排版提取）。**字段以本表为准，其余各节只引用不复述**：

| 字段 | 类型 | 渲染到 |
| --- | --- | --- |
| id | str | 卡头／徽标／深链 |
| name / module / role / pri / goal | str | 卡头元数据、字段表 |
| core ＋ points[] | str / str[] | 【1.核心口径】 |
| userStory | str | 抽屉【2.用户故事】（MD 不展示） |
| interact[] | str[] | 【3.交互细节】＝抽屉【3.功能描述】 |
| conf | str | 【4.置信度】 |
| acs[] | {id, given, when, then, demo} | 【2.验收标准】＝抽屉【4.验收 GWT】 |
| target | {view, tab?, fn 或 act, pre?} | 定位 |
| arch? | str | 架构承接行（有架构件时，见 B6） |

- **两个投影的映射**：MD【1】＝抽屉【1】＝core+points；MD【3】＝抽屉【3.功能描述】＝interact；MD【2】＝抽屉【4】＝acs；MD【4】＝conf；userStory 只在抽屉
- `acs[].id`＝story.id＋`-ACn`（§2）；`acs[].demo`＝`{how:'live'|'note'|'none', path, view?, tab?, fn?, act?, fault?, pre?, note?}`——how=note 时 `note` 必填（注记元素定位：裸元素 id 或 `data-note=key`），供 G2 断言注记存在且非空
- **target 必填 view＋(fn|act) 二选一**，选填 tab、pre：fn＝演示函数名（FN_REGISTRY）；act＝**裸元素 id（不带 #）**；pre＝前置态（定位前需选中的记录/tab/角色）
- JSON 样例（新原型照此结构）：

```json
{"id":"REQ-v1.0-006","name":"数据绑定映射","module":"数据绑定","role":"R1","pri":"P0","goal":"GOAL-1",
 "core":"…","points":["…"],"userStory":"作为…","interact":["入口→操作→反馈"],"conf":"…【确证（来源）】",
 "acs":[{"id":"REQ-v1.0-006-AC1","given":"…","when":"…","then":"…",
   "demo":{"how":"live","path":"报告定义页 · 选中草稿 · 点「＋新增绑定」","view":"defs","fn":"editBindDs"}}],
 "target":{"view":"defs","fn":"editBindDs"}}
```

- 定位入口**只有两个**：`locateFromCard(id)`（REQ 级）、`locateFromAC(acId)`（AC 级），挂 window；不得另立他名

### B3 抽屉与标注 UI

- 右侧滑出抽屉，FAB 常驻入口（图标＋「需求卡片」＋数量徽标）；骨架只建一次，搜索/筛选只重绘列表区，**绝不重建壳**〔事故〕壳重建重放滑入动画，抽屉每点一次闪一次
- 卡片一行三列（编号／名称与元数据／▶ 定位按钮）；默认全折叠；每次打开抽屉重置 storyOpen/storyQuery/storyModule
- reqtag 徽标布点：导航尾部／视图 H2 尾部／表格列头／关键控件旁／**modal 标题与面板内**
- **三种定位路径状态矩阵**（唯一口径，取代一切「保留/清空」散述）：

| 路径 | 抽屉 | storyQuery/chip | storyOpen | modal |
| --- | --- | --- | --- | --- |
| 卡片▶→页面 locateFromCard | 保持开（已开时不动查询/筛选；抽屉经深链/首次打开则走重置） | 不动 | 不变 | 先关（formDirty 弹确认） |
| 页面徽标→抽屉 | 开 | 清空、回「全部」 | ＝该卡 | — |
| AC「演示▶」→页面 locateFromAC | 保持开 | 清空、回「全部」 | ＝该卡 | 先关（同上） |

- **五连契约**（页面徽标→抽屉，缺一即「点了没反应」）：①开抽屉不重建壳 ②清过滤——必达优先于保筛选〔事故〕目标被活动搜索词筛掉、点击像没反应 ③storyOpen 展开且正文可见 ④卡头滚入视口（`list.scrollTop = el.offsetTop - list.offsetTop - 6`；不用 scrollIntoView center，会把卡头推出视口〔事故〕）⑤高亮描边≈2s。展开/滚动/高亮必须包 `requestAnimationFrame` 重取节点〔事故〕列表重绘替换旧节点，同步取到的节点操作全部落空
- 徽标嵌在可点击元素内必须 `event.stopPropagation()`；「页面标注」总开关只切 CSS 类，不重绘
- 视觉为**默认值**（可按目标系统设计语言覆盖）：徽标 mono≈10px、遮罩≤10% 黑、滑入≈0.2s
- 深链 `#story=REQ-xxx` 延时调 locate；卡片 MD「定位原型」链接即写此 hash

### B4 三大契约

**C1 徽标一致性＋定位即展示**
- 全局不变量：`∀ story：target.view 渲染后的 DOM 中存在 [data-req=story.id]`——首建与追加同规（lint⑥）
- 徽标覆盖所有功能载体：菜单/按钮/tab/区块标题/modal 标题与面板内；「列表页有、点进弹窗没有」＝断裂；弹窗内徽标点击走定位链
- 定位切换：定位到新 AC/REQ **先关当前 modal**（formDirty 守卫）再切视图执行——弹窗叠弹窗、页面在弹窗后跳＝断裂〔事故〕点 AC 演示后旧弹窗不关，落点被遮住
- **定位即展示**（卡片▶是硬验收点）：四连断言①view/tab 正确 ②act/fn 有副作用 ③落点 `getBoundingClientRect()` 在视口内 ④定位条/高亮指向它。首屏可见性不设硬要求（功能藏几级交互都合法），但定位必须把功能展示给用户〔事故〕locate 丢了 act 执行＋徽标长在依赖演示数据的条件行上，点完定位页面无变化
- 落点必须**无条件渲染**（不依赖选中记录/过滤态）；动态重复元素禁裸 id（用 class＋data）；**最不利状态复核**固定三组合：`fault=success`＋空态对象（如空草稿）＋带过滤词

**C2 自然可达性**
- 每个 demo 载体除抽屉定位外，必须有**纯界面操作路径**——「只有定位能打开、界面无入口」＝演示孤岛，不合格
- `demo.path` 是**可执行点击序列**（非描述文字）：从 seed 默认状态出发 ≤4 步的 UI 操作（如 `报告定义页 · 选中草稿 · 点「＋新增绑定」`）；核查按序列点击后断言载体可见
- 入口不得绑在依赖演示数据状态的条件渲染上〔事故〕「配置」按钮只在草稿且有绑定行时渲染，而 seed 唯一草稿是空草稿→零入口；空态对象必须提供「新增/起步」入口

**C3 AC 演示映射＋覆盖表**
- 每条 AC 带 demo（B2 schema）；抽屉 AC 行渲染「演示▶」（live）或原位标注（note/none 不伪装成可演示）
- 故障档说明文案由 demo.fault 反查生成，单一数据源，勿手写字符串
- **覆盖阈值：live≥90%、note≤10%、none≤5% 且逐条在汇报点名**；覆盖率数字写进交付汇报
- 补载体先登记 demo 再写功能，覆盖表驱动〔事故〕曾 99 条 AC 中 18 条一致性对比类全无载体，评审点开对不上

### B5 视图与演示数据模式（仅预留型/框架型需求适用，普通系统可跳过）

- 一视图多子页（tab 承载不同 REQ 族）必须有**可见页签条**（当前态高亮、可互切）；卡片定位 tab 与页签条共用状态；手动进视图清残留 tab 回主表〔事故〕用户把「两条 REQ 定位到同视图、内容不同」当 bug 报障
- 预留型需求按语义选承载视图（**按本系统实际命名**）：数据/证据类→列表/台账；规则/配置类→规则库/配置页；流程/版本类→时间线/播放器；判定类→钻取
- 台账配「数据状态」开关演示三分状态（正常／缺基准→数据不足／等待到数→暂无）；规则库逐条标「V1.0 落地／预留」及预留原因；播放器示例做命中矩阵
- 示例文案依赖 fault 时必须在 render 时按当前 fault 重建〔事故〕模块级常量固化首次 fault，切开关后不更新
- 演示数据对上冻结件示例的数字（区间/最高值/点数）——评审会拿原型对正文核

### B6 与架构文档对齐（目标仓有架构提案/ADR 时）

1. 读完全部架构件（提案正文＋裁定/决策点＋修订记录），提取修改点编号（M-x）、骨架代号、已裁决策、预留编码/接口名、落地映射、示例走查结论
2. 卡片加「架构承接」字段行（需求→M-x/骨架/既有机制）；已裁口径织入核心口径；验收可加架构可验条款
3. 原型：STORIES 条目加 arch 字段渲染到卡片表格；页脚与抽屉副标题标架构件版本。区分「需求语义」（冻结件原话）与「架构选择」（提案裁定，标来源）

## C. 交付门

**跑 `scripts/lint-prototype.py <原型.html> [卡片.md]` 全绿 ＋ 浏览器断言清单全绿，才交付**。一次会话内跑完，不留给用户当验收员。

**lint（静态，脚本强制）**：① 静态 id 唯一＋动态 id 表达式唯一（同表达式多模板给 ⚠ 提示人工确认不同屏）② demo.fn ∈ FN_REGISTRY 且 dry-run 无语法错误 ③ demo.fault ∈ 故障档 options ④ ac.id 以父 story.id 开头且 n 连续 ⑤ 零外链（含无引号属性/srcset/url()/@import/fetch/meta refresh）⑥ 徽标载体（剔除 STORIES 块后按 data-req/reqtag/locateFromCard 三类匹配，零命中报红）⑦ 双源对账（set 相等＋条数相等＋无重复＋`-AC\d+` 全位数＋全角空格卡头兼容）⑧ schema 校验（必填字段/target view+fn|act/acs 非空/demo.how 合法/live 有 fn|act/note 有 note 字段）。G3 浏览器侧逐 story 切 target.view 后断言 `[data-req=id]` 元素数≥1

**浏览器断言 checklist**：
- **G1 定位即展示四连**：逐卡 locateFromCard，含最不利三状态（fault=success／空态对象／过滤态）
- **G2 AC 级执行**：逐条 live AC 点「演示▶」断言无异常＋可见副作用；note AC 断言 `demo.note` 指向的注记元素存在且 `textContent` 非空——堵「注册了跑不通」「note 没写也过关」
- **G3 反向徽标**：逐个点页面 reqtag（含嵌在可点击行/Tab 内的）断言五连；带活动搜索词/chip 时断言过滤被清、目标可见
- **G4 剧情副作用**：上传后版本+1、坏文件不污染数据、reset 可恢复、故障档按钮禁用态、角色 chip 数≥详设角色表
- **G5 标注开关**：关→页面徽标全隐、抽屉内卡片不受影响

**浏览器断言脚本陷阱**（G1-G5 执行时注意）：`dispatchEvent(new Event('change'))` 默认不冒泡，要传 `{bubbles:true}`；toast 断言收集全队列取末条（3.2s 自动移除）；长 JS 字符串拆多条短 js() 调用，防拼串语法错。

## D. 迭代与运维
